# Day 23 · 对象生命周期与栈堆

## 今日目标
- 梳理对象从构造到析构的完整过程
- 理解栈对象与堆对象的生命周期差异
- 学会用 RAII 思想管理资源

## 学习内容

### 对象诞生：构造顺序

一个对象有多个成员时，析构构造顺序如下：

1. 父类构造（Day26 讲继承）；
2. 成员对象按**声明顺序**构造（不是初始化列表顺序！）；
3. 自身构造函数体。

```cpp
class A { public: A() { std::cout << "A\n"; } };
class B { public: B() { std::cout << "B\n"; } };
class C {
    B b;
    A a;
public:
    C() { std::cout << "C\n"; }
};
// 创建 C：B -> A -> C（按声明顺序 b, a）
```

### 对象死亡：析构顺序

析构顺序与构造**完全相反**：

1. 自身析构函数体；
2. 成员对象按声明**逆序**析构；
3. 父类析构。

### 栈 vs 堆：生命周期

```cpp
void f() {
    Student s1;              // 栈对象：出 f() 自动析构
    Student* p = new Student; // 堆对象：不 delete 就一直活着
    // ...
    delete p;                // 手动析构
}                            // s1 在这里自动析构
```

| 对象位置 | 构造 | 析构 |
|---|---|---|
| 栈上 | 定义时 | 出作用域自动 |
| 堆上 | new 时 | delete 时 |
| 静态/全局 | 程序启动早期 | 程序结束时 |

### 临时对象

有些表达式会产生临时对象，语句结束就销毁：

```cpp
Student makeStudent() { return Student("x"); }
makeStudent();    // 临时对象，这行结束就析构
```

### RAII 思想

**资源获取即初始化**（Resource Acquisition Is Initialization）：把资源封装在对象里，构造时申请、析构时释放。这样即使函数提前 return 或抛异常，析构也会被自动调用，资源不会泄漏。

```cpp
class File {
    FILE* f_;
public:
    File(const char* path) { f_ = fopen(path, "r"); }
    ~File() { if (f_) fclose(f_); }
};
```

后面学智能指针，本质上就是 RAII 的具体应用。

### 常见坑

- 返回局部对象的地址或引用：函数返回后对象已析构；
- new 了对象不 delete：内存泄漏；
- 栈对象取地址存起来，函数返回后变悬空指针。

## 核心重点
- 成员按声明顺序构造，析构逆序
- 栈对象出作用域自动析构，堆对象要手动 delete
- 临时对象在语句结束时销毁
- RAII：把资源绑在对象生命周期上，自动释放
- 不要返回局部对象的指针/引用
