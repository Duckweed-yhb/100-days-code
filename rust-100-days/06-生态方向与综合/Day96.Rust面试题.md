# Day96 Rust 面试题

> 目标：把 Rust 岗最高频的几个概念——所有权、生命周期、trait object、智能指针、Send/Sync、Pin、async 原理——用三五行话讲清楚。

## 1. 所有权与借用规则

**问：Rust 的所有权规则是什么？**

- 每个值有且只有一个所有者
- 所有者离开作用域，值被 drop（释放）
- 同一时刻要么一个可变引用 `&mut T`，要么多个不可变引用 `&T`，不能兼得

借用检查器在编译期强制执行这些，所以没有数据竞争、没有悬垂指针。

## 2. 生命周期

**问：生命周期标注是干什么的？**

生命周期标注（`'a`）不改变引用实际活多久，只是**告诉编译器多个引用之间的关系**。比如函数返回的引用，到底是入参 A 的还是入参 B 的，编译器要靠标注推断。多数情况有生命周期省略规则，不用手写。

## 3. dyn trait object vs 泛型静态分发

**问：`dyn Trait` 和泛型 `<T: Trait>` 有什么区别？**

- 泛型：**静态分发**，编译期单态化，为每个具体类型生成一份代码，零开销
- `dyn Trait`：**动态分发**，运行期通过虚表查表调用，有一次间接跳转，但能装不同类型

追求性能用泛型；要装异构集合（如 `Vec<dyn Draw>`）用 dyn。

## 4. Box / Rc / Arc / RefCell 区别

**问：这几个智能指针分别什么时候用？**

| 类型 | 所有权 | 线程安全 | 内部可变性 |
|---|---|---|---|
| `Box<T>` | 独占 | 是 | 无 |
| `Rc<T>` | 引用计数多所有权 | **否**（单线程） | 无 |
| `Arc<T>` | 引用计数多所有权 | 是 | 无 |
| `RefCell<T>` | 独占 | — | 运行期检查借用 |

- 递归类型/ trait object：`Box`
- 单线程需要多个所有者：`Rc`
- 多线程多所有者：`Arc`
- 要在「不可变引用」里改数据、又想编译过：`RefCell`
- 多线程 + 内部可变：`Arc<Mutex<T>>`

## 5. Send 和 Sync

**问：Send/Sync 是什么？**

- `Send`：类型可以安全地**转移所有权到另一个线程**
- `Sync`：类型可以安全地**被多线程共享引用**（`&T` 能 Send）

绝大多数类型自动实现它们。`Rc` 不是 Send/Sync（引用计数非原子），`Arc` 才是。编译器靠这俩保证「无畏并发」。

## 6. Pin 与自引用

**问：Pin 是解决什么问题的？**

Rust 默认允许移动值（内存地址变了）。但 Future 自引用（结构体字段指向自己内部）时，一移动指针就悬垂了。`Pin<P>` 保证背后的值不被移动，async/await 生成的状态机就靠它安全。普通业务代码很少直接写 Pin。

## 7. async 运行时原理

**问：async/await 在 Rust 里是怎么跑的？**

`async fn` 不自己开线程，而是编译成一个实现 `Future` 的状态机。它本身**不会执行**，必须由运行时（tokio 等）**轮询（poll）**：准备好了就继续，没就绪就挂起，等事件来了再 poll。所以一个线程能跑成千上万任务（M:N 协程）。

## 8. ? 与错误转换

**问：`?` 运算符做了什么？**

`?` 遇到 `Err` 就提前返回错误，遇到 `Ok(v)` 拆出 `v`。它还会自动通过 `From` trait 把错误类型转成函数返回的错误类型——所以不同错误能在同一个函数里用 `?` 串联。

## 今日小结

- 所有权：一值一主、作用域 drop、读写互斥
- 生命周期标注只表达引用关系，不改实际寿命
- 泛型静态分发零开销，dyn 动态分发装异构类型
- Box/Rc/Arc/RefCell 按「所有权 + 线程 + 内部可变」选
- Send/Sync 是并发安全的基石；Pin 防移动保 Future 自引用
- async 是被运行时轮询的状态机，? 自动转错误并提前返回
