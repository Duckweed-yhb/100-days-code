## 第一步：需求拆解

短链服务的核心故事：用户提交一个长 URL → 系统存起来、生成一个短码 → 访问短码时 302 跳转到原 URL。

把功能切成「必做」和「加分」：

**必做（MVP）：**

- `POST /shorten`：提交长 URL，返回短码
- `GET /{code}`：根据短码 302 跳转
- 短码重复时要处理
- 数据存 SQLite（零部署）

**加分（做不完不勉强）：**

- 内存 LRU 缓存热点短码
- 访问计数
- 简单过期时间

## 第二步：模块划分

按职责拆成几个模块，别把所有东西堆 main：

```
shortener/
├── src/
│   ├── main.rs       # 启动：建路由、绑端口
│   ├── config.rs     # 读配置（端口、数据库路径）
│   ├── store.rs      # 存储抽象：存/取短码（SQLite 实现）
│   ├── cache.rs      # 内存缓存（可选）
│   └── error.rs      # 统一错误类型
└── Cargo.toml
```

每个模块干一件事：`store` 只管数据存取，不管 HTTP；`main` 只管接线。以后换存储（SQLite→Postgres）只改 `store`。

## 第三步：数据结构与接口设计

先把「长什么样」定下来：

```rust
// 一条短链记录
struct Link {
    code: String,      // 短码，如 "a8Xk2"
    long_url: String,  // 原始长 URL
    created_at: i64,
}

// 存储 trait：上层面向它编程，不关心底层是 SQLite 还是内存
trait Store {
    async fn save(&self, long_url: &str) -> Result<String>;  // 返回短码
    async fn lookup(&self, code: &str) -> Result<Option<String>>; // 返回长 URL
}
```

再定 HTTP 接口：

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| POST | `/shorten` | `{"url": "https://..."}` | `{"code": "a8Xk2"}` |
| GET | `/{code}` | — | 302 跳转 |
