# Day61 计算机体系结构回顾

> 目标：在写内核之前，先把 CPU 是怎么取指执行、有哪些特权级、内存为什么要分层讲清楚，后面看 rCore 代码才不会一脸懵。

从今天开始我们进入第五阶段：**用 Rust 写操作系统**。在碰任何一行内核代码之前，得先补一点硬件常识。你不需要会设计 CPU，但要知道 CPU 把你的代码当成什么东西在跑。

## 冯·诺依曼结构：程序和数据都住在内存里

今天的计算机基本都是**冯·诺依曼结构（von Neumann architecture）**。核心思想一句话：**指令和数据不加区别地存放在同一块内存里**，CPU 按地址把指令一条一条取出来执行。

CPU 内部的几个关键部件：

```
        ┌──────────────────────── 内存 (DRAM) ────────────────────────┐
        │  存放指令(代码) + 数据(变量/栈)，按字节编址                  │
        └───────▲───────────────────────────────────────┬───────────┘
                │ 取指/取数                              │ 写回
        ┌───────┴───────────────────────────────────────▼───────────┐
        │                    CPU 芯片内部                              │
        │  ┌──────────┐   ┌──────────┐   ┌──────────┐                 │
        │  │  寄存器   │→ │  译码    │→ │  执行    │→ 写回寄存器/内存  │
        │  │ (Regs)   │   │ (Decode) │   │  (ALU)   │                 │
        │  └──────────┘   └──────────┘   └──────────┘                 │
        │         ▲                                                    │
        │         │ 程序计数器 pc 指向下一条要取的指令地址              │
        └─────────┴────────────────────────────────────────────────────┘
```

执行一条指令的经典三步：**取指（fetch）→ 译码（decode）→ 执行（execute）**，然后 `pc` 指向下一条，循环往复。这个环形流水线是理解一切控制流的基础——函数调用、中断、异常，本质都是在改 `pc`。

## 特权级：凭什么你不能改页表

用户程序直接去改内存管理单元、关中断，系统就乱套了。于是 CPU 设计了**特权级（privilege level）**：低权限的用户态干不了危险操作，必须陷入（trap）到高权限的内核态去做。

RISC-V 定义了三种特权级（数字越小权限越高）：

| 特权级 | 名字 | 用途 | 谁在跑 |
|---|---|---|---|
| M | Machine mode 机器模式 | 最底层，开机首先跑这里，初始化硬件 | 固件 / OpenSBI |
| S | Supervisor mode 监管模式 | 操作系统内核住这里，管内存、调度、设备 | **rCore 内核** |
| U | User mode 用户模式 | 跑普通应用，权限受限 | 你写的用户程序 |

开机流程是 `M → S → U` 的降级过程：

```
上电
 │
 ▼
M mode (OpenSBI 固件：初始化时钟、串口等)
 │  把权限交给内核 (mret / 跳转到内核入口)
 ▼
S mode (rCore 内核：做自己的初始化)
 │  准备好用户进程，sret 回到 U
 ▼
U mode (用户程序运行)
 │  遇到 ecall / 缺页 / 外设中断
 ▼
S mode (内核处理 trap，处理完再 sret 回 U)
```

> 小知识：我们写 rCore 时其实很少直接碰 M mode，因为 QEMU 里 OpenSBI 已经替我们跑了 M mode 的固件。内核通过 SBI 调用（也是一次 ecall）让固件帮忙关机、输出字符。

## CSR：给内核用的"特殊寄存器"

普通程序用通用寄存器 `x0~x31`。内核要控制 CPU 行为，得读写一组**控制状态寄存器（Control and Status Register, CSR）**。RISC-V 的 CSR 是带编号的特殊寄存器，用专门的 `csrr`（读）/`csrw`（写）指令访问。

后面会反复见到的 S 模式 CSR：

| CSR | 作用 |
|---|---|
| `sscratch` | 内核临时寄存用，trap 时用来交换指针 |
| `stvec` | trap 入口地址向量，告诉 CPU 出事了跳哪 |
| `sepc` | 发生 trap 时的指令地址，处理完从这继续 |
| `scause` | trap 原因（是缺页？是 ecall？是外设中断？） |
| `stval` | trap 附加信息（比如缺页时的出错地址） |
| `sstatus` | 状态位，比如之前是不是在用户态、中断是否开着 |
| `satp` | 页表基址寄存器，打开虚拟内存就靠它 |

记住一张图：**出事时 CPU 自动把 `sepc`/`scause`/`stval` 填好，跳 `stvec` 指向的入口；内核处理完，从 `sepc` 取地址 `sret` 回去。** 这就是 Day69 的全部骨架。

## 内存层次：为什么要有 cache

内存比 CPU 慢得多。CPU 算一条指令只要几纳秒，去 DRAM 取数据要上百纳秒。为了不拉胯，硬件做了**金字塔式的存储层次（memory hierarchy）**，越往上越快越小越贵：

```
        越快越小越贵
        ┌─────────────┐
        │   寄存器      │  几十个，CPU 算东西直接用，最快
        ├─────────────┤
        │  L1/L2 Cache │  几 KB~几 MB，SRAM，CPU 片上
        ├─────────────┤
        │  L3 Cache    │  共享缓存
        ├─────────────┤
        │   内存 DRAM   │  GB 级，掉电就没，慢
        ├─────────────┤
        │   磁盘/SSD   │  TB 级，持久化，最慢
        └─────────────┘
        越慢越大越便宜
```

对写内核的人来说，记住两点就够：

1. **访问局部性**：刚访问过的内存，附近的大概率马上还要用，所以 cache 按"行"预取。这也是为什么数组比链表友好。
2. **Cache 对软件大部分透明**，但在做设备寄存器映射、多核同步时要留意一致性问题，初学阶段先知道有这层就行。

## 今日小结

- 冯·诺依曼：指令和数据都在内存里，CPU 循环"取指→译码→执行"
- RISC-V 三级特权：M（固件）> S（内核）> U（用户程序），开机 `M→S→U`
- CSR 是内核专用的特殊寄存器，trap 现场靠 `stvec/sepc/scause/stval/satp` 这几个
- 内存是金字塔：寄存器 → cache → 内存 → 磁盘，越往上越快越小
