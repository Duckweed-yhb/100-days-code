# Day70 页表与虚拟内存

> 目标：搞懂 RISC-V SV39 三级页表怎么把"虚拟地址"翻译成"物理地址"，`satp` 怎么打开虚拟内存，以及 TLB 和 `sfence.vma` 是干嘛的。

从今天起，CPU 看到的地址不再是真地址了。每个进程都以为自己独占一整坨内存——这就是**虚拟内存（virtual memory）**，翻译靠硬件的**页表（page table）**。

## 为什么要虚拟内存

没有它的话：

- 每个进程直接用物理地址，A 进程乱写就能踩翻 B 进程和内核。
- 程序加载时必须找一块连续大物理内存，碎片严重。

有了它：

```
进程 A 的视角: 0x0000 ~ 0xFFFF 连续一整块
进程 B 的视角: 0x0000 ~ 0xFFFF 连续一整块
        ↓ 各自页表翻译 ↓
物理内存里: 东一块西一块，但互相看不见
```

好处：**隔离（进程间不能互踩）+ 抽象（每个进程都觉得自己有完整地址空间）**。

## 页与页帧

虚拟内存按固定大小切，RISC-V 默认 **4KB 一页（page）**。对应的物理内存叫**页帧（page frame）**。地址的切分：

```
虚拟地址:
┌─ 虚拟页号(VPN) ─┬─ 页内偏移 offset(12位, 0~4095) ─┐
│                  │  offset 部分翻译时不动，直接拼到物理地址末尾
└──────────────────┴───────────────────────────────────┘
```

offset 低 12 位原样保留，上面的高位拿去页表里查它落在哪个物理页帧（PPN）。

## SV39：三级页表

RISC-V 支持 SV39 模式：用 **三级**页表。39 位虚拟地址切成 9+9+9+12：

```
 38 ... 30  29 ... 21  20 ... 12   11 ... 0
┌─ VPN[2] ─┬─ VPN[1] ─┬─ VPN[0] ─┬─ offset ─┐
│  第3级索引 │ 第2级索引 │ 第1级索引 │ 页内偏移 │
└──────────┴─────────┴─────────┴─────────┘
```

每级页表是一张 512 项的表，每项叫 **PTE（Page Table Entry）**，长这样：

```
PTE: ┌────────── PPN (物理页帧号) ──┬─ RSW ─┬─ 标志位 ┐
     │                              │       │ V/R/W/X/U/G/A/D...
```

关键标志位：

| 位 | 含义 |
|---|---|
| `V` | valid，这项是否有效 |
| `R/W/X` | 读/写/执行权限（全 0 表示这是指向下一级页表的指针） |
| `U` | 用户态是否可访问 |

## 地址翻译 Walk 流程

CPU（或软件）翻译一个虚拟地址时，**三级查表**：

```
satp 给出根页表(第3级)的物理地址
        │
        ▼
VPN[2] 索引 → 得到下一级页表物理地址
        │
        ▼
VPN[1] 索引 → 再下一级页表物理地址
        │
        ▼
VPN[0] 索引 → 最终 PTE，里面是目标物理页帧号 PPN
        │
        ▼
物理地址 = PPN << 12 | offset
```

画成树：

```
        根页表 (satp 指向)
        ├─[VPN2=0] → 二级页表A
        │             ├─[VPN1=0] → 三级页表
        │             │             └─[VPN0=*] → 物理页帧 (VPN→PPN)
        │             └─[VPN1=1] → ...
        └─[VPN2=1] → 二级页表B ...
```

## satp：打开虚拟内存的总开关

`satp` 寄存器里：MODE 设成 `Sv39`，再放根页表的物理页帧号。写好后，**之后所有地址都自动过页表翻译**。内核启动时切页表，就是换 `satp`。

```rust
// 内核代码片段，需在 rCore 环境运行，不能在普通 cargo 项目直接跑
unsafe fn set_satp(root_ppn: usize) {
    // satp 寄存器：最高 4 位 MODE 填 8 表示 Sv39，低位放根页表的物理页帧号
    let satp_val = (8usize << 60) | root_ppn;
    asm!("csrw satp, {}", in(reg) satp_val);
    asm!("sfence.vma"); // 写完 satp 立即刷新 TLB，否则可能按旧映射跑
}
```

## TLB 与 sfence.vma

每次查三次表太慢，硬件做了 **TLB（Translation Lookaside Buffer）**：把最近用过的 VPN→PPN 结果缓存起来。

问题：页表改了，TLB 里还是旧映射。所以软件改完页表后，必须执行 `sfence.vma` 让 TLB 失效：

```rust
unsafe fn sfence() {
    asm!("sfence.vma zero, zero", options(nostack));
}
```

rCore 里每次地址空间切换（换进程）都会写 `satp` + `sfence.vma`，否则会按旧进程的映射跑。

## 今日小结

- 虚拟内存：每个进程以为独占地址空间，靠页表翻译成物理地址
- RISC-V SV39：39 位虚地址切 9+9+9+12，三级页表，每页 4KB
- PTE 里存 PPN 和权限位（V/R/W/X/U）；walk 三次查表拼出物理地址
- `satp` 选 Sv39 并指向根页表；改完映射要 `sfence.vma` 刷 TLB
