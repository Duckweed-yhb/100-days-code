# Day75 文件系统 easy-fs

> 目标：看懂 rCore 的极简文件系统 easy-fs 分层——从块设备、块缓存、磁盘 inode 到内存 inode，搞懂文件、目录、打开文件表怎么组织。

内存掉电就没。要持久化，就得把数据写到块设备（QEMU 里是一个镜像文件）。管理"怎么在一块裸磁盘上组织文件"的，就是**文件系统（file system）**。

## 磁盘的本质：一串块

磁盘不会按"文件"给你数据，它只按固定大小的**块（block，easy-fs 里 512 字节）**读写：

```
块号:   0    1    2    3    4    5   ...
      ┌────┬────┬────┬────┬────┬────┐
      │超级│inode│inode│数据│数据│数据│ ...
      └────┴────┴────┴────┴────┴────┘
```

文件系统要自己规定：哪几块放元数据、哪几块放文件内容、哪个 inode 对应哪个文件。

## easy-fs 分层结构

rCore 的 easy-fs 分五层，从下往上：

```
┌─────────────────────────────────────┐
│  目录/文件接口 (File/Dir)           │  你 open/read/write 面对的
├─────────────────────────────────────┤
│  内存 inode (Inode)                  │  把磁盘 inode 缓存进内存
├─────────────────────────────────────┤
│  块缓存 BlockCache                   │  把磁盘块缓存进内存，改了再回写
├─────────────────────────────────────┤
│  块设备 BlockDevice                   │  按块读写镜像文件
└─────────────────────────────────────┘
```

为什么要缓存？磁盘慢、内存快。把常用的块缓在内存里，多次读写不用每次都碰磁盘。

## 超级块与位图

磁盘开头有个**超级块（super block）**，记录整个文件系统的元信息：

```
超级块:
  总块数 / 总 inode 数
  inode 位图起始块        ← 记录哪个 inode 号空闲
  数据块位图起始块        ← 记录哪个数据块空闲
```

- **inode 位图**：一位对应一个 inode，0 空闲、1 占用。新建文件就找一个 0 位改成 1。
- **数据块位图**：一位对应一个数据块，分配文件内容块靠它。

这两个位图就是文件系统的"空闲账本"。

## inode：一个文件的档案

每个文件/目录有一个 **inode（index node）**，记录：

```
inode:
  文件类型 (文件 / 目录)
  文件大小
  数据块号列表 (直接块 + 间接块)
```

- **目录**是一种特殊 inode，它的内容是一组"文件名 → inode 号"的映射表。
- 你 `open("a.txt")`：内核先查根目录 inode，在目录块里找到 `a.txt` 对应的 inode 号，再去读那个 inode，拿到数据块号，最后读数据。

```
open("file.txt")
  根目录 inode ──查名字──► inode 号 7
  inode 7 ──读内容块──► 文件数据
```

## 打开文件表

进程通过 `fd`（文件描述符）访问文件。内核维护两张表：

```
进程的 fd_table:
  fd=0 → 标准输入
  fd=1 → 标准输出
  fd=2 → 标准错误
  fd=3 → 某个打开的文件 → 指向全局的 InnerInode
```

- **每个进程**有自己的 fd 表（所以 fork 后子进程继承一份）。
- **系统级**维护打开的 inode 计数，最后一个使用者关掉才真正释放块。

## 今日小结

- 磁盘按块读写，文件系统靠超级块 + 两张位图（inode 位图/数据块位图）管空闲
- easy-fs 五层：块设备 → 块缓存 → 磁盘 inode → 内存 inode → 文件/目录接口
- 目录是特殊 inode，内容是"文件名 → inode 号"映射
- fd 是进程级句柄，背后指向全局共享的打开 inode
