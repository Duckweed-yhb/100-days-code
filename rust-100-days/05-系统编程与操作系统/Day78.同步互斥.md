# Day78 同步互斥

> 目标：搞懂临界区、为什么要关中断实现锁、信号量怎么用，以及死锁的四个必要条件——多线程不打架的全套基本功。

Day77 末尾那个 `cnt += 1` 出错，根源是多个线程同时动了共享数据。今天解决它：**互斥（mutual exclusion）**保证同一时刻只有一个线程进临界区，**同步（synchronization）**保证线程之间按正确顺序配合。

## 临界区

**临界区（critical section）**：访问共享资源、且必须独占执行的那段代码。

```rust
// 错误示范
unsafe { CNT += 1; }   // ← 这整句(编译后三条指令)就是临界区
```

规则很简单：**同一时刻，最多一个线程在临界区里。**

## 怎么实现一把锁

### 办法一：关中断

最简单粗暴的锁——进临界区前**关中断**，出了再开。RISC-V 里改 `sstatus.SIE` 位：

```rust
// 内核代码片段，需在 rCore 环境运行，不能在普通 cargo 项目直接跑
// 关中断期间，调度器不会被时钟中断触发，也就不会切走当前线程
unsafe fn disable_intr() {
    asm!("csrsi sstatus, 1");   // set sstatus 的 SIE 位
}
unsafe fn enable_intr() {
    asm!("csrci sstatus, 1");
}
```

为什么关中断就能互斥？因为在单核上，只要不被时钟中断打断，当前线程就不会被切走，临界区自然独占。rCore 教学版早期就是这么干的。

缺点：多核就不行了——另一个核上的线程照样能进来。多核要靠**原子指令**。

### 办法二：原子指令

硬件提供"读-改-写一气呵成"的指令。RISC-V 的 `amoswap`（原子交换）/`lr/sc`（加载保留/存储条件）就是干这个的：

```
lock 被设为 0 = 空闲, 1 = 占用
线程想进: 原子地把 lock 从 0 换成 1，看换之前是不是 0
  是 0 → 我拿到锁，进临界区
  是 1 → 别人拿着，忙等/让出
```

```rust
// 概念示意：自旋锁 spinlock
pub struct SpinLock { locked: AtomicBool }
impl SpinLock {
    pub fn lock(&self) {
        while self.locked.compare_exchange(false, true).is_err() {
            // 拿不到就原地转，忙等
        }
    }
    pub fn unlock(&self) { self.locked.store(false); }
}
```

拿不到锁**原地打转**叫**自旋（spin）**，适合临界区极短的场景。

## 信号量 Semaphore

锁是"二值"的（要么独占要么没有）。**信号量（semaphore）**是更一般的计数器：

```
信号量 S = 一个整数 + 等待队列
P 操作(申请): S -= 1;  if S < 0, 阻塞排队
V 操作(释放): S += 1;  if S <= 0, 唤醒一个排队者
```

- **互斥信号量**：初值 1，就是一把锁。
- **资源信号量**：初值 N，代表有 N 个同类资源可分配。

经典的**生产者-消费者**问题就用两个信号量解决：

```
空缓冲槽信号量 empty = N
满缓冲槽信号量 full  = 0

生产者: P(empty); 放数据; V(full)
消费者: P(full);  取数据; V(empty)
```

## 互斥 vs 同步

| | 互斥 | 同步 |
|---|---|---|
| 解决什么 | 同一资源不能同时多人用 | 线程间要按约定顺序执行 |
| 例子 | cnt += 1 要加锁 | 生产者先放、消费者才能取 |
| 工具 | 互斥锁(Mutex) | 信号量、条件变量 |

## 死锁：四个必要条件

两个线程各拿一把锁，又互相等对方手里的锁，就**死锁（deadlock）**了，双方永远卡住。

```
线程A: 拿了锁1, 等锁2
线程B: 拿了锁2, 等锁1    ← 永远僵持
```

死锁成立必须**同时**满足四个条件（Coffman 条件）：

1. **互斥**：资源一次只能一个人用
2. **持有并等待**：拿着手里的，还要等别人的
3. **不可抢占**：别人不能强行抢你手里的锁
4. **循环等待**：A 等 B、B 等 A，成环

破坏任意一个就能防死锁。最常用的是**破坏循环等待**：规定所有线程必须按固定顺序申请锁。

## 今日小结

- 临界区要独占；单核可关中断实现锁，多核要原子指令（自旋锁）
- 信号量 P/V：申请减一并可能阻塞，释放加一并可能唤醒
- 互斥管"同一资源不抢"，同步管"按顺序配合"
- 死锁四条件：互斥、持有并等待、不可抢占、循环等待，破坏其一即可
