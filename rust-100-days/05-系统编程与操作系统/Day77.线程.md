# Day77 线程

> 目标：搞懂线程和进程到底差在哪、为什么线程切换比进程轻，以及 rCore 里"共享地址空间的多个执行流"是怎么落地的。

前面我们说的"进程"，有独立地址空间。但如果你想在一个程序里同时算两个东西，又让它们共享同一份内存，怎么办？这就需要**线程（thread）**。

## 进程 vs 线程

```
进程: 资源分配的单位
  ┌─────────────────────────┐
  │ 独立地址空间(页表)        │
  │ 独立 fd 表                │
  ├─────────────────────────┤
  │  线程1: 一份寄存器/栈      │
  │  线程2: 另一份寄存器/栈    │  ← 多个线程共享上面的资源
  └─────────────────────────┘
```

关键区别：

| | 进程 | 线程 |
|---|---|---|
| 地址空间 | 各自独立 | **同进程内共享** |
| fd 表/文件 | 各自独立 | 同进程内共享 |
| 私有的东西 | 几乎全部 | 只有自己的栈和寄存器 |
| 切换成本 | 重（要换页表、刷 TLB） | 轻（只切栈和寄存器） |

## 为什么线程切换更轻

回顾 Day68：上下文切换主要是存/恢复 callee-saved 寄存器。再回顾 Day70：切进程要换 `satp` 指向新页表，还要 `sfence.vma` 刷 TLB。

```
进程切换:
  __switch 寄存器  +  换 satp(页表)  +  sfence.vma(刷TLB)   ← 重

同进程内线程切换:
  __switch 寄存器  ← 页表不变，TLB 不用刷                    ← 轻
```

因为线程共享地址空间，**页表不用动**，TLB 里的映射照样有效。这就是线程"轻"的根本原因。

## 线程私有的是什么

多个线程共享地址，但它们不能共用一份栈——否则函数调用会踩乱。所以每个线程有：

- **自己的内核栈**（trap 时存现场用）
- **自己的用户栈**（跑用户代码时的栈）
- **自己的 TaskContext**（Day68 那个）

共享的：代码段、数据段、堆、fd 表、地址空间。

```
线程A 栈          共享堆/代码         线程B 栈
   │                                  │
   └──── 共享同一份 MemorySet ────────┘
```

## rCore 里的模型

rCore 在 ch8 引入线程，把原来的 TCB 拆成两层：

```
进程(Process): 持有 MemorySet、fd_table 等共享资源
   └── 线程(Thread): 每个线程有自己的 TaskContext、栈、状态
```

一个进程可以派生多个线程，它们跑在同一份地址空间里，被调度器独立调度。

## 多线程带来的新问题

线程共享内存是好事，但也带来麻烦：两个线程同时改一个变量，结果就不确定了。这就是**数据竞争（data race）**。

```
线程1: cnt = cnt + 1   (读 cnt → 加 1 → 写回)
线程2: cnt = cnt + 1   (同时也在读/写)
```

三条指令交错执行，最后 cnt 可能只加了一次。解决办法就是 Day78 的**同步互斥**。

## 今日小结

- 进程是资源单位（独立地址空间），线程是 CPU 调度单位（共享进程资源）
- 线程切换轻：只换栈和寄存器，页表不变、TLB 不刷
- 每个线程私有自己的栈和 TaskContext，共享代码/数据/堆/fd 表
- 共享内存带来数据竞争，需要 Day78 的同步互斥机制
