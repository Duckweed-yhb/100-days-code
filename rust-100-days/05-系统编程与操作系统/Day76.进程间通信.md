# Day76 进程间通信

> 目标：搞懂管道（pipe）怎么用一块内核环形缓冲让两个进程传数据，为什么读空/写满会阻塞，以及它为什么能和文件描述符统一起来。

每个进程有独立地址空间，互相看不见对方的内存。那父子进程、兄弟进程之间怎么传消息？答案是**进程间通信（Inter-Process Communication, IPC）**。rCore 教学里最核心的 IPC 就是**管道（pipe）**。

## 管道是什么：一根半透明的水管

想象一根水管：一端塞进去写数据，另一端读出来。内核在中间存一个**环形缓冲区**，两端进程通过它交换字节流：

```
写端进程 A                内核环形缓冲              读端进程 B
         ── write() ──►  [a b c _ _ _ _ _]  ── read() ──►
                         头 ↑        ↑ 尾
```

- 管道是**字节流**，没有消息边界：你分两次写 3+5 字节，对面可以一次读 8 字节。
- 管道是**单向**的：一个 fd 专门写，另一个 fd 专门读。

## 环形缓冲实现

内核用一个固定大小的数组 + 头尾指针实现：

```rust
// 内核代码片段，需在 rCore 环境运行，不能在普通 cargo 项目直接跑
pub struct Pipe {
    buf: [u8; RING_SIZE],     // 环形缓冲，比如 512 字节
    head: usize,              // 读位置
    tail: usize,              // 写位置
}

impl Pipe {
    fn read(&mut self, out: &mut [u8]) -> usize {
        // 从 head 拷到 out；空了就返回让调用者阻塞
    }
    fn write(&mut self, data: &[u8]) -> usize {
        // 从 tail 写入；满了就让调用者阻塞
    }
}
```

```
空:  head == tail
满:  (tail+1) % SIZE == head
```

环形缓冲的好处：读写都只动指针，搬数据不挪位置，O(1)。

## 读空/写满：阻塞

管道和普通文件最大的区别是**会阻塞**：

| 情况 | 行为 |
|---|---|
| 读端去读，但缓冲空了 | 读进程 **Blocked**，等写端塞数据 |
| 写端去写，但缓冲满了 | 写进程 **Blocked**，等读端取走数据 |

这就接上了 Day73 的状态机：进程读管道发现空，就把自己设成 Blocked 挂起；写端写入后唤醒它。

```
读进程: 管道空 → Blocked
写进程: 写入数据 → 唤醒读进程 → 读进程变 Ready
```

## 和文件描述符统一

rCore 设计的精髓：**管道也是一种 FileDesc**。

```rust
// 内核代码片段，需在 rCore 环境运行，不能在普通 cargo 项目直接跑
pub enum FileDesc {
    Pipe(Arc<Pipe>),          // 管道
    File(Arc<Inode>),         // 普通文件
    // ...
}
```

于是用户态 `read(pipe_read_fd, buf, n)` 和 `read(file_fd, buf, n)` 用的是**同一个系统调用**，只是背后对象不同。这就是 Unix "一切皆文件" 的思路——管道、文件、设备都抽象成 fd，统一用 read/write 操作。

## pipe() 系统调用

用户创建管道：

```c
int pipe(int fds[2]);
// fds[0] = 读端, fds[1] = 写端
```

典型用法——父子进程配合：

```
1. 父进程 pipe(&fds) 拿到读端/写端两个 fd
2. fork()：子进程继承这两个 fd
3. 父进程关掉读端，只留写端，往里写
4. 子进程关掉写端，只留读端，从里读
```

```
 父进程 ──写──► [内核 pipe 缓冲] ──读──► 子进程
```

## 今日小结

- 管道是内核里的一块环形缓冲，提供单向字节流 IPC
- 环形缓冲用 head/tail 指针，读写 O(1)
- 读空/写满会让进程 Blocked，对方操作后唤醒——和 Day73 状态机联动
- 管道被抽象成 FileDesc，和普通文件共用 read/write，这是"一切皆文件"
