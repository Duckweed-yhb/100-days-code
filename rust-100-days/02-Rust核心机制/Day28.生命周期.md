# Day28 生命周期

> 目标：理解 Rust 如何用「生命周期标注」保证引用不会悬垂，并记住三条省略规则，让你大多数时候不用手写它。

## 先别怕：生命周期到底在解决什么

还记得 Day11 学借用时，编译器会拒绝悬垂引用吗？比如下面这段是编译不过的：

```rust
fn main() {
    let r;
    {
        let x = 5;
        r = &x; // x 马上就要离开作用域被销毁
    }          // x 在这里死了
    println!("{}", r); // r 悬垂了！编译器会报错
}
```

编译器怎么知道 `r` 比 `x` 活得久？它靠的就是给每个引用算出它有效的**作用域长度**——这就是**生命周期（lifetime）**。绝大多数时候编译器自己能推断，你完全不用写。

只有一种情况它会卡住：**函数返回的引用，和多个输入引用有关联，编译器无法判断返回值到底该跟谁活得一样长。** 这时才需要你手动标注。

## 标注语法：`'a`

生命周期标注以撇号 `'` 开头，放在 `&` 后面：

```rust
&i32        // 普通引用（编译器自己推断生命周期）
&'a i32     // 显式标注生命周期 'a
&'a mut i32 // 显式标注的可变引用
```

注意：生命周期标注**不改变任何引用的实际寿命**，它只是告诉编译器「这几个引用之间寿命有什么关系」，好让它做检查。

## 经典例子：返回较长的那个字符串

```rust
// 编译不过！因为编译器不知道返回的引用和 x、y 的关系
// fn longest(x: &str, y: &str) -> &str {

fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() {
        x
    } else {
        y
    }
}

fn main() {
    let s1 = String::from("长一点的字符串");
    let result;
    {
        let s2 = String::from("短");
        result = longest(s1.as_str(), s2.as_str());
        println!("较长的是 {}", result);
    }
}
```

`'a` 的意思是：**x、y、返回值这三者，被绑在同一个生命周期 `'a` 上**，而 `'a` 等于两者中较短的那个。所以返回的引用在较短的输入失效之前都有效——编译器据此拒绝任何让返回值悬垂的用法。

你不需要完全背下这套推理，只要记住：**当函数返回一个引用，而它可能来自多个参数时，就要加 `<'a>` 标注。**

## 三条省略规则：大多数时候不用写

你可能会疑惑：平时写函数怎么没加过 `'a`？因为编译器有三条**生命周期省略规则（lifetime elision rules）**，能自动推断：

1. **规则1（输入）**：每个引用参数都拿到一个独立的生命周期。`fn f(x: &i32)` → `fn f<'a>(x: &'a i32)`。
2. **规则2（输出）**：如果只有一个输入生命周期参数，就把它赋给所有输出。`fn f(x: &i32) -> &i32` → `fn f<'a>(x: &'a i32) -> &'a i32`。
3. **规则3（方法）**：如果有多个输入参数且其中一个是 `&self`，就把 `self` 的生命周期赋给所有输出。

三条规则走完还推不出来（就像 `longest` 有两个输入引用），编译器才报错让你手写标注。**所以你 90% 的代码都不用碰生命周期语法。**

## 结构体里存引用

如果结构体的字段是个引用，也必须给它标注生命周期——保证这个结构体实例不能比它引用的数据活得更久：

```rust
struct ImportantExcerpt<'a> {
    part: &'a str, // 这个引用得和 'a 一样长
}

fn main() {
    let novel = String::from("Call me Ishmael. Some years ago...");
    let first_sentence = novel.split('.').next().unwrap();
    let excerpt = ImportantExcerpt { part: first_sentence };
    // novel 比 excerpt 活得久，所以合法
}
```

## 静态生命周期 `'static`

有一种特殊生命周期叫 `'static`，表示「存活于整个程序运行期间」。所有字符串字面量都是 `'static`：

```rust
let s: &'static str = "我硬编码在二进制里，整个程序都在";
```

新手别一看到报错就乱加 `'static`——先想清楚引用的数据到底存多久。

## 今日小结

- 生命周期是引用有效的作用域，编译器默认自动推断，你通常不用写
- 标注语法 `&'a T`：不改变真实寿命，只是告诉编译器各引用寿命的关联
- 函数返回引用且可能来自多个参数时（如 `longest(x, y)`），必须手动写 `<'a>`
- 三条省略规则覆盖大多数情况；推不出来编译器才让你标注
- 结构体字段是引用时要标生命周期；`'static` 是贯穿整个程序的生命周期（字符串字面量）
