# Day28 生命周期

> **前置知识**：Day11 引用与借用、Day12 切片
> **难度**：进阶
> **预计阅读时间**：25 分钟
> **代码说明**：本章代码都放在**同一个** `main.rs` 里。标了 ⚠️ 的块是故意编不过的示例，用来看报错，别照抄。
> 每块前面标了 `📦`（能单独跑）或 `🧩`（依赖上面的块，别单拎出来）。

目标：理解 Rust 如何用生命周期标注保证引用不会悬垂，并记住三条省略规则，让你大多数时候不用手写它。

## 先别怕：生命周期到底在解决什么

Day11 学借用时见过，编译器会拒绝悬垂引用。下面这段就是编不过的：

⚠️ 本块是故意的错误示例，编译不过，别照抄。它的用途是让你看清编译器怎么拦人：

```rust
fn main() {
    let r;
    {
        let x = 5;
        r = &x; // x 马上就要离开作用域被销毁
    }          // x 在这里死了
    println!("{}", r); // r 悬垂了
}
```

`rustc` 给出的原话（本地实跑的结果）：

```
error[E0597]: `x` does not live long enough
  |
4 |         let x = 5;
  |             - binding `x` declared here
5 |         r = &x;
  |             ^^ borrowed value does not live long enough
6 |     }
  |     - `x` dropped here while still borrowed
7 |     println!("{}", r);
  |                    - borrow later used here
```

编译器怎么知道 `r` 比 `x` 活得久？它给每个引用算出一个有效的**作用域长度**，这就是**生命周期（lifetime）**。绝大多数时候编译器自己就能推断，你完全不用写。

只有一种情况它会卡住：**函数返回的引用，和多个输入引用有关联，编译器判断不出返回值该跟谁活得一样长。** 这时才需要手动标注。

---

## 标注语法：`'a`

生命周期标注以撇号 `'` 开头，写在 `&` 后面：

⚠️ 本块是语法示意，不是能编译的完整代码，看写法就行：

```rust
&i32        // 普通引用（生命周期由编译器推断）
&'a i32     // 显式标注生命周期 'a
&'a mut i32 // 显式标注的可变引用
```

`'a` 里那个 `a` 只是名字，叫 `'b`、`'x` 都行，写成 `'a` 是习惯。标注不改变任何引用的实际寿命，它只告诉编译器「这几个引用之间的寿命是什么关系」，好让它做检查。

`&mut` 是可变引用（Day11 讲过），`&'a mut i32` 表示这个可变引用的生命周期是 `'a`。

## 经典例子：返回较长的那个字符串

📦 本块能单独跑：

```rust
// 去掉下面这个标注就会编不过：编译器不知道返回值和 x、y 是什么关系
// fn longest(x: &str, y: &str) -> &str {

fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() {
        x
    } else {
        y
    }
}

fn main() {
    let s1 = String::from("长一点的字符串");
    let result;
    {
        let s2 = String::from("短");
        result = longest(s1.as_str(), s2.as_str());
        println!("较长的是 {}", result);
    }
}
```

`as_str()` 把 `String` 借成 `&str`，`&str` 就是字符串切片，Day12 的内容。

`'a` 的意思是：x、y、返回值这三者被绑到同一个生命周期 `'a` 上，而 `'a` 取两者中较短的那个。返回的引用在较短的输入失效之前都有效，编译器据此拒绝任何让返回值悬垂的用法。

这套推理不用背，记住一句就够：**函数返回引用，而它可能来自多个参数时，加 `<'a>` 标注。**

---

## 三条省略规则：大多数时候不用写

你可能疑惑，平时写函数怎么没加过 `'a`。因为编译器有三条**生命周期省略规则（lifetime elision rules）**，能自动推断：

1. **规则1（输入）**：每个引用参数拿到一个独立的生命周期。`fn f(x: &i32)` 等价于 `fn f<'a>(x: &'a i32)`。
2. **规则2（输出）**：只有一个输入生命周期参数时，把它赋给所有输出。`fn f(x: &i32) -> &i32` 等价于 `fn f<'a>(x: &'a i32) -> &'a i32`。
3. **规则3（方法）**：有多个输入参数、其中一个是 `&self` 时，把 `self` 的生命周期赋给所有输出。

三条走完还推不出来（`longest` 有两个输入引用就是这样），编译器才报错让你手写。**所以 90% 的代码都不用碰生命周期语法。**

## 结构体里存引用

字段是引用时，结构体也必须标生命周期，保证实例不会比它引用的数据活得更久：

📦 本块能单独跑：

```rust
struct ImportantExcerpt<'a> {
    part: &'a str, // 这个引用至少和 'a 一样长
}

fn main() {
    let novel = String::from("Call me Ishmael. Some years ago...");
    let first_sentence = novel.split('.').next().unwrap();
    let excerpt = ImportantExcerpt { part: first_sentence };
    println!("{}", excerpt.part);
}
```

`novel.split('.').next().unwrap()` 取第一个句号之前的片段，`unwrap()` 是 Day18 和 Day25 都见过的用法。

## 静态生命周期 `'static`

📦 本块能单独跑：

```rust
fn main() {
    let s: &'static str = "我硬编码在二进制里，整个程序都在";
    println!("{}", s);
}
```

`'static` 表示「存活于整个程序运行期间」。字符串字面量都是 `'static`，因为它们被编进二进制文件，程序一跑就在，程序结束才消失。

看到报错就往引用上加 `'static` 是常见误区。先想清楚引用的数据到底能活多久：数据本身是本地构造的，加 `'static` 也救不了，编译器照样拦。

---

## 今日小结

- 生命周期是引用有效的作用域，编译器默认自动推断，你通常不用写
- 标注语法 `&'a T`：不改变真实寿命，只是告诉编译器各引用寿命的关联
- 函数返回引用且可能来自多个参数时（如 `longest(x, y)`），必须手动写 `<'a>`
- 三条省略规则覆盖大多数情况；推不出来编译器才让你标注
- 结构体字段是引用时要标生命周期；`'static` 是贯穿整个程序的生命周期（字符串字面量）
