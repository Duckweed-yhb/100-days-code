# Day31 闭包

> 目标：学会写「能记住周围变量的匿名函数」闭包，理解它怎么捕获环境、怎么被编译器分类成 Fn / FnMut / FnOnce。

## 什么是闭包

你写过普通函数：`fn add_one(x: i32) -> i32 { x + 1 }`。闭包（closure）长得像一段「临时的、没名字的函数」，最大的本事是：**它能把定义它那一刻周围的变量一起抓进来，存着用**。

打个比方：普通函数像一个独立工位，桌上只有别人递进来的材料（参数）；闭包像一个带抽屉的工位，除了递进来的材料，它还把自己工位抽屉里的东西（外部变量）也一起带上了。

闭包通常存进一个变量里，之后像调函数一样调它：

```rust
// 闭包语法：参数放在竖线 | | 之间，后面跟函数体
let expensive_closure = |num: u32| -> u32 {
    println!("calculating...");
    num // 最后一个表达式是返回值
};

let result = expensive_closure(5); // 像函数一样调用
```

## 闭包可以省类型标注

普通函数必须写明参数和返回值类型；闭包**不强制**写，编译器会根据**第一次调用**推断类型，然后把这个类型锁死。

```rust
// 不写类型，让编译器猜
let add_one_v3 = |x| x + 1;        // 单行可省略大括号
println!("{}", add_one_v3(10));    // 第一次调用：x 被推断为 i32
```

但注意「锁死」这件事：

```rust
let example = |x| x; // 类型还没定
let s = example(String::from("hello")); // 第一次传 String，x 被锁成 String
// let n = example(5); // 编译报错！x 已经是 String，不能再传 i32
```

对比一下四种写法（同一个函数 `x + 1`）：

```rust
fn  add_one_v1(x: i32) -> i32 { x + 1 } // 普通函数，必须标类型
let add_one_v2 = |x: i32| -> i32 { x + 1 }; // 完整标注的闭包
let add_one_v3 = |x|             { x + 1 }; // 省略类型
let add_one_v4 = |x|               x + 1  ; // 单行连大括号都省了
```

> 想可读性高一点，手动写类型标注完全没问题；想省事就靠编译器推。

## 闭包怎么捕获环境

这是闭包区别于普通函数的核心。下面这段闭包内部用了外部的 `x`：

```rust
let x = 4;
let equal_to_x = |z| z == x; // 闭包悄悄抓住了外部的 x
let y = 4;
assert!(equal_to_x(y)); // 闭包里的 x 就是外面那个 4
```

普通函数根本看不到这个 `x`，因为它不在参数里、也不是全局变量。闭包却能「顺手」把它抓进来——这就是「捕获环境」。

## 三种捕获方式：Fn / FnMut / FnOnce

Rust 会根据闭包**怎么用**抓进来的变量，自动把它归到三个 trait 之一。你不用急着背，先有个印象：

| trait | 怎么用环境变量 | 能不能多次调用 |
|---|---|---|
| `Fn` | 只读地借用环境变量（不可变借用） | 可以，随便调多少次 |
| `FnMut` | 会修改环境变量（可变借用） | 可以，但调用期间独占 |
| `FnOnce` | 拿走环境变量的所有权 | 最多调一次（调完变量就被消费了） |

它们是「由松到紧」的关系：一个 `Fn` 闭包也满足 `FnMut`，一个 `FnMut` 也满足 `FnOnce`。

## 把闭包当参数或存进结构体

闭包本身没有名字，类型又五花八门，所以要把它当参数传、或存进结构体字段时，得用**泛型 + trait bound** 告诉编译器「我要一个能接受 u32、返回 u32 的闭包」。

官方书举了个缓存器 `Cacher` 的例子：它包着一个闭包，第一次算完就把结果存起来，后面直接用，避免重复计算。

```rust
struct Cacher<T>
where
    T: Fn(u32) -> u32, // T 必须是一个「吃 u32、吐 u32」的闭包
{
    calculation: T,        // 存着那个闭包
    value: Option<u32>,    // 算过就缓存结果
}

impl<T: Fn(u32) -> u32> Cacher<T> {
    fn new(calculation: T) -> Cacher<T> {
        Cacher { calculation, value: None }
    }

    fn value(&mut self, arg: u32) -> u32 {
        match self.value {
            Some(v) => v, // 已经算过，直接返回缓存
            None => {
                let v = (self.calculation)(arg); // 真正调闭包
                self.value = Some(v);
                v
            }
        }
    }
}

fn main() {
    let mut c = Cacher::new(|x| x * 2); // 传入闭包
    assert_eq!(c.value(3), 6);
    assert_eq!(c.value(3), 6); // 第二次直接用缓存，不再调闭包
}
```

运行上面命令看看输出：`c.value(3)` 第一次算成 6，第二次命中缓存。

## move 闭包：强制拿走所有权

默认闭包能借就借。如果在闭包前加 `move`，就强制把捕获变量的**所有权**搬进闭包：

```rust
let x = vec![1, 2, 3];
let equal_to_x = move |z| z == x; // x 的所有权被搬进闭包
// println!("{:?}", x); // 编译报错！x 已经不归 main 管了
```

这个关键字今天先混个脸熟——Day37 学多线程时你会发现，把数据送进新线程几乎必须用 `move`。

## 什么时候会用到闭包

现在你可能觉得闭包用处不明显。别急，下一天的迭代器里它会高频出现：`.map(|x| x + 1)`、`.filter(|x| x > 0)` 里竖线后面全是闭包。后面线程、GUI、各种库的回调也都是闭包。

## 今日小结

- 闭包是能**捕获环境变量**的匿名函数，常存进变量或当参数传
- 类型标注可省略，编译器按第一次调用推断并锁死
- 按捕获方式自动分为 `Fn`（只读借用）/ `FnMut`（可变借用）/ `FnOnce`（拿所有权，只能调一次）
- 当参数或结构体字段时，用泛型 + `Fn` 系列 trait bound
- `move` 强制把环境变量所有权搬进闭包（多线程常用）
