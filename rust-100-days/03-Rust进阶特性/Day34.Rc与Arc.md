# Day34 Rc 与 Arc

> 目标：理解「一个值只能有一个所有者」这条铁律什么时候不够用，学会用 `Rc<T>` 做单线程多所有权共享，并知道它的多线程双胞胎 `Arc<T>`。

## 一个值只能有一个主人

到目前为止，Rust 的铁律是：**一个值同一时刻只有一个所有者**。赋值或传参时所有权移动，旧主人就不能再用了。

但现实里经常出现「一份数据，好几处地方都要读」的情况。比如一张图里，同一个节点被多条边指向；又比如配置对象被多个模块共享。这时候移动所有权就不够用了——你不能把同一份数据同时给两个人。

打个比方：普通所有权像「房子只有一本房产证，过户给你我就没了」。`Rc` 像「这份文件印了多份复印件，谁都能看，最后一个人看完才扔」。

## Rc<T>：引用计数

`Rc<T>`（reference counting，引用计数）在堆上存一份数据，旁边记一个**强引用计数**。每多一个所有者，计数 +1；每少一个，计数 -1；计数归 0 时，数据才真正被 drop。

```rust
use std::rc::Rc;

#[derive(Debug)]
enum List {
    Cons(i32, Rc<List>), // 注意这里是 Rc<List>，不是 Box<List>
    Nil,
}

use List::{Cons, Nil};

fn main() {
    // a 是主链表：5 -> 10 -> Nil
    let a = Rc::new(Cons(5, Rc::new(Cons(10, Rc::new(Nil)))));
    println!("创建 a 后计数 = {}", Rc::strong_count(&a)); // 1

    // 让 b 也共享 a：3 -> (a)
    let _b = Cons(3, Rc::clone(&a));
    println!("创建 b 后计数 = {}", Rc::strong_count(&a)); // 2

    {
        // 让 c 也共享 a：4 -> (a)
        let _c = Cons(4, Rc::clone(&a));
        println!("创建 c 后计数 = {}", Rc::strong_count(&a)); // 3
    } // c 离开作用域，自动 drop，计数回到 2
    println!("c 离开后计数 = {}", Rc::strong_count(&a)); // 2
}
```

运行上面命令看看输出：计数从 1 涨到 3，c 离开后回到 2。

## 关键细节

- **`Rc::clone(&a)` 只增加计数，不深拷贝数据**。它非常快，只是改一个整数。这和普通的 `.clone()`（往往真的复制一份数据）要区分开——有人特意写成 `Rc::clone(&a)` 就是为了提醒读者「这不是深拷贝」。
- **`Rc::strong_count(&a)`** 查看当前强引用数。
- `Rc<T>` 只提供**不可变共享**——你能有很多人同时读，但不能透过 `Rc` 拿到可变引用。想要共享又可变？那是 Day35 `RefCell` 的事。

> 注意：`Rc<T>` **不能跨线程**。它的引用计数不是原子操作，多线程下会算错。需要跨线程时用下面的 `Arc<T>`。

## Arc<T>：线程安全版 Rc

`Arc<T>`（Atomically Reference Counted，原子引用计数）和 `Rc<T>` 用法几乎一模一样，区别在于它的引用计数用**原子操作**更新，所以是线程安全的，可以跨线程共享。

| | `Rc<T>` | `Arc<T>` |
|---|---|---|
| 计数更新 | 普通整数，快 | 原子操作，略慢 |
| 能不能跨线程 | 不能 | 能 |
| 头文件 | `std::rc::Rc` | `std::sync::Arc` |
| 典型场景 | 单线程内多所有者共享 | 多线程共享同一份数据 |

经验法则很简单：**单线程用 `Rc`，一想到跨线程就换 `Arc`**。它们 API 完全一样，换过来几乎不用改代码。

```rust
use std::sync::Arc; // 注意是 sync 不是 rc

fn main() {
    let a = Arc::new(5);
    let b = Arc::clone(&a);
    println!("计数 = {}", Arc::strong_count(&a)); // 2
    // 后面 Day39 会看到 Arc 配合 Mutex 在多线程里共享可变数据
}
```

运行上面命令看看输出：`计数 = 2`。`a` 和 `b` 指向堆上同一个 `5`，没有复制任何数据。

## Rc::clone 不是深拷贝

再强调一次，因为它太容易被名字误导。假设有一份很大的 `Vec`：

```rust
use std::rc::Rc;

fn main() {
    let big = Rc::new(vec![1; 1_000_000]); // 一百万个数在堆上
    let also_big = Rc::clone(&big); // 几乎瞬间完成，只把计数从 1 加到 2
    println!("计数 = {}", Rc::strong_count(&big)); // 2
    // 数据本身从头到尾只有一份，没有复制那一百万个元素
}
```

对比一下：如果你调的是 `big.as_ref().clone()`（真去克隆那个 Vec），就要把一百万个元素整个复制一遍，慢得多。看到 `Rc::clone(&x)` 你就知道：这是「又多了个主人」，不是「再印一份」。

## 一个常见误区

新手常问：「`Rc` 能让我同时有两个可变引用吗？」——不能。`Rc` 解决的是**多个所有者读同一份不可变数据**的问题。借用规则依然在：就算包在 `Rc` 里，你也不能同时借出两个 `&mut`。要在「多所有者」下修改内部数据，需要 `Rc<RefCell<T>>` 这个组合，下一天就讲。

## 今日小结

- Rust 默认单一所有权；多处共享只读数据时用 `Rc<T>`
- `Rc<T>` 维护强引用计数，归零时才 drop；`Rc::clone` 只加计数不深拷贝
- `Rc::strong_count` 查看引用数
- `Rc<T>` 只能单线程用；跨线程换 `Arc<T>`（原子引用计数），API 几乎一样
- `Rc`/`Arc` 都只提供不可变共享，要可变得配 `RefCell`（单线程）或 `Mutex`（多线程）
