# Day59 项目实战

> 目标：从今天起开始做一个属于你自己的小项目。今天先选题、做设计、列出分步开发计划，明天收尾打磨。

## 为什么要有这个项目

前面 58 天你一直在“跟着教程走”：每个例子都有标准答案。但学语言的真正门槛是**独立从 0 做出一个能跑的东西**。接下来两天，我们把工程化阶段学的所有东西——命令行参数、文件 IO、错误处理、测试、日志、甚至网络——综合用到一个项目里。

## 选题建议

选题原则：**一周内能做完、但又能用上这阶段学的主要知识点**。别贪大。推荐三类：

### 方向一：增强版命令行工具（推荐新手）

在 minigrep 基础上扩展，或者另做一个：

| 项目 | 用到的知识点 |
|---|---|
| 统计文件行数/词数的 `mywc` | 文件遍历、迭代器、命令行参数 |
| 批量重命名工具 | `std::fs`、路径处理、错误处理 |
| Markdown 待办清单管理器 | serde 读写 JSON、命令行、CRUD |
| 番茄钟计时器 | 时间、控制台输出、`ctrlc` 信号处理 |

### 方向二：小型 HTTP 服务

在 Day55 线程池服务器基础上扩展：

| 项目 | 用到的知识点 |
|---|---|
| 静态文件服务器 | TCP、HTTP、按路径返回文件 |
| 待办事项 API（返回 JSON） | HTTP、serde、内存 HashMap |
| 简单 URL 短链接服务 | HashMap、重定向（301）、serde |

### 方向三：和你的方向结合

你在做开源操作系统训练营——也可以写个小工具辅助学习：比如解析 ELF 文件头、统计符号表、格式化打印页表项等。这类项目用 `std::fs` 读二进制 + 手动解析字节就行，正好练 Rust 的字节处理。

> 选一个你自己**真的会用**的东西。自己不用的项目，写一半就没动力了。

## 开发计划（分步走）

不管选哪个项目，都按这个节奏来。今天（Day59）完成前四步，明天（Day60）完成后三步。

### 第 1 步：写一句话需求

先别写代码，用纸笔或 Markdown 回答：

- 这个工具叫什么？
- 用户输入什么？（命令行参数？HTTP 请求？）
- 它输出什么？（打印到终端？写文件？返回 JSON？）
- 成功和失败分别是什么样？

例如：“我要做一个 `mywc`：命令行传一个文件路径，打印该文件的行数、词数、字符数。文件不存在时打印错误并退出码 1。”

### 第 2 步：画接口草图

把核心数据结构和函数签名先列出来（不写实现）：

```rust
// 伪代码，先想清楚有哪些组件
struct Stats { lines: usize, words: usize, chars: usize }

fn analyze(text: &str) -> Stats;
fn print_report(stats: &Stats);
```

这一步逼你把“怎么做”先想清楚，而不是边写边乱。

### 第 3 步：建工程、跑通最小骨架

```powershell
cargo new mywc
cd mywc
```

按 Day53 的工程化套路：逻辑放 `src/lib.rs`，`main.rs` 当薄壳。先让它能 `cargo run` 打印一句“hello”，再往里填肉。

### 第 4 步：TDD 逐个加功能

每加一个功能：先写一个失败的测试 → 实现到测试过 → 再下一个。例如 `mywc`：

```rust
#[test]
fn counts_lines() {
    assert_eq!(analyze("a\nb\nc").lines, 3);
}
#[test]
fn counts_words() {
    assert_eq!(analyze("hello rust world").words, 3);
}
```

```powershell
cargo test
```

### 第 5 步：接命令行/网络（明天做）

把 lib.rs 的逻辑接到 `main.rs`：解析参数、读文件、调 `analyze`、打印结果。

### 第 6 步：加错误处理和日志（明天做）

用 Day56 的知识：库用 thiserror，main 用 anyhow；关键步骤用 `log` + `env_logger`。

### 第 7 步：写 README 和打包（明天做）

写清楚怎么安装、怎么用；试着 `cargo build --release` 出一个可执行文件。

## 今天的具体任务

1. 从上面的方向里选一个项目，或者自己定一个。
2. 用 10 分钟写一句话需求和接口草图（记在项目的 `TODO.md` 或你自己的笔记里）。
3. `cargo new` 建项目，搭好 lib.rs / main.rs 骨架，跑通 `cargo run`。
4. 用 TDD 实现最核心的 1~2 个纯函数（不碰 IO），测试绿。

## 今日小结

- 选题原则：一周能做完、真的会用、覆盖这阶段知识点
- 开发节奏：一句话需求 → 接口草图 → 工程骨架 → TDD 逐个加功能 → 接 IO → 错误/日志 → README
- 逻辑放 lib.rs、main.rs 当薄壳，从 Day53 沿用
- 今天完成前四步：选题、设计、骨架、核心函数测试

## 动手任务

1. 确定你的项目题目，写一句话需求。
2. 建项目，把核心数据结构和 2~3 个函数签名定下来（不写实现）。
3. 给核心函数写至少 2 个测试用例，先跑红再实现到绿。

> 提示：如果纠结选什么，就做 `mywc`——它和 minigrep 同构，第二天能直接套 Day53 的模板，不会卡住。
