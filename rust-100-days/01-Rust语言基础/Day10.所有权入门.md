# Day10 所有权入门

> 目标：理解 Rust 最核心的概念——所有权（ownership），搞清楚栈与堆、移动（move）、克隆（clone）和 Copy。

## 为什么要有所有权

写 C/C++ 时，内存要自己 `malloc` / `free`：忘了释放就**内存泄漏**，提前释放就**悬垂指针**，重复释放更会直接崩溃。靠垃圾回收（GC）的语言（Java、Go）省心，但运行时有开销，也不适合操作系统这种底层场景。

Rust 选了第三条路：**所有权（ownership）**——在**编译期**就把内存管理全部检查好，运行时没有 GC。这是 Rust 区别于所有其他语言的招牌，也是新手最需要慢慢消化的一关。

## 先认识：栈（stack）和堆（heap）

程序运行时的内存大致分两块：

- **栈**：像一摞"餐盘"，放下去、拿出来都很快。里面的数据大小**固定**、生命周期短。整数、浮点这些基本类型都在栈上。
- **堆**：像一个大仓库，要存一块大小不固定、可能很大的数据时，得先"申请"一块地方（记下地址），用完还要"归还"。`String`、`Vec` 这种能长大的数据存在堆上。

所有权要管的，主要就是**堆上的数据什么时候归还**。

## 所有权的三条规则（先背下来）

1. **每个值都有一个所有者（owner）**——持有它的那个变量。
2. **同一时刻，有且只有一个所有者**。
3. **当所有者离开作用域**（所在的花括号 `{}` 结束）时，这个值会被自动释放。

> 作用域（scope）就是一对 `{}` 圈起来的范围。变量出了 `}` 就失效了。

## 移动（move）：堆上数据赋值后，原变量就不能用了

先看一段会编译报错的代码：

```rust
fn main() {
    let s1 = String::from("hello");   // s1 是这个堆字符串的所有者
    let s2 = s1;                      // "把 s1 给 s2"

    println!("{}", s1);               // ❌ 报错：borrow of moved value: `s1`
}
```

为什么报错？因为 Rust 认为：如果 `s1` 和 `s2` 都指向同一块堆内存，那当 `main` 结束时，**两个变量都会尝试释放这块内存**——这就是"双重释放"，是 C 里最危险的 bug 之一。

为了杜绝它，Rust 在 `let s2 = s1;` 这一步做了个干脆的决定：**把所有权从 s1 移动（move）给了 s2，同时让 s1 失效**。从此以后只有 `s2` 是所有者，出作用域时释放一次就够了。这就是"移动语义"。

> 生活比喻：像房子过户。你把房子过户给朋友后，这房子法律上就是他的了，你（s1）不能再拿来做任何事；哪天房子（内存）要处理，也由他（s2）来。

## 栈上的数据：赋值是"复制"，不会失效

那为什么 `let x = 5; let y = x;` 之后 `x` 还能用？因为整数这种存在**栈**上、大小固定、复制成本极低的数据，Rust 默认是**直接复制一份**，不存在双重释放问题：

```rust
fn main() {
    let x = 5;
    let y = x;          // x 在栈上，复制一份给 y，x 还能用
    println!("{} {}", x, y);   // 正常，x 和 y 都是 5
}
```

这种"赋值即复制、原变量不失效"的类型，实现了 **`Copy` trait（拷贝 trait）**。Rust 里常见的 `Copy` 类型有：所有整数（`i32`、`u64`…）、浮点（`f64`）、布尔 `bool`、字符 `char`，以及由它们组成的元组。

> 判断小窍门：如果一个值的全部数据都能在栈上放下（不碰堆），它通常就是 `Copy` 的；像 `String`、`Vec` 这种在堆上分配的，就不是 `Copy`，赋值就会 move。

## 真想要一份独立的副本：clone()

如果堆上的数据你确实想**深拷贝一份**（栈上栈上都复制，两块独立内存），显式调用 `.clone()`：

```rust
fn main() {
    let s1 = String::from("hello");
    let s2 = s1.clone();        // 真的复制了一份堆上的数据

    println!("s1 = {}, s2 = {}", s1, s2);   // 两个都能用，互不影响
}
```

> 注意：`clone()` 是要付出性能代价的（真的去复制整块堆内存）。所以 Rust **不会偷偷**帮你 clone，要你明确写出来。能用引用（明天学）就别动不动 clone。

## 函数调用也会转移所有权

把一个非 `Copy` 类型的值传给函数，同样会发生 move——所有权从调用者手里移交给了函数参数：

```rust
fn main() {
    let s = String::from("hello");
    takes_ownership(s);            // s 的所有权移进函数

    // println!("{}", s);          // ❌ 到这 s 已经失效了

    let x = 5;
    makes_copy(x);                 // x 是 i32，Copy，传一份副本
    println!("{}", x);             // ✅ x 还能用
}

fn takes_ownership(some_string: String) {
    println!("{}", some_string);
}                                  // some_string 出作用域，自动释放

fn makes_copy(some_int: i32) {
    println!("{}", some_int);
}
```

如果函数想把所有权"还回去"，可以把值作为返回值传出来：

```rust
fn main() {
    let s1 = gives_ownership();          // 函数造一个 String 给 s1
    let s2 = String::from("hello");
    let s3 = takes_and_gives_back(s2);   // s2 被移走，函数又返回一个给 s3
    println!("{} {}", s1, s3);           // s2 已失效，s1、s3 有效
}

fn gives_ownership() -> String {
    String::from("我造的")
}

fn takes_and_gives_back(a: String) -> String {
    a                                    // 把 a 原样返回，所有权交回
}
```

每次都靠传参、返回值倒腾所有权实在麻烦——Rust 给的解法就是**引用与借用**，明天见。

## 今日小结

- 所有权三条规则：每个值有且仅有一个所有者；所有者离开作用域时值自动释放。
- 栈上固定大小的数据（整数、浮点、bool、char）实现了 `Copy`，赋值是复制，原变量不失效。
- 堆上数据（`String`、`Vec`）赋值或传参会发生 **move**，原变量立刻失效，杜绝双重释放。
- 想要独立的堆副本，显式调用 `.clone()`，但它有性能开销。
- 函数传值会转移所有权；想"还回去"可以把它作为返回值。
