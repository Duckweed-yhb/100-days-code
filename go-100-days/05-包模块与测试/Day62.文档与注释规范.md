# Day 62 · 文档与注释规范

## 今日目标
- 学会写 Go 风格的注释
- 理解 godoc 文档约定
- 养成导出符号必注释的习惯

## 学习内容

### 注释即文档

Go 不单独写文档，注释就是文档。godoc 工具直接从注释生成网页。

### 导出符号必注释

任何大写开头的函数、类型、变量，都应该有注释，且以名字开头：

```go
// User 表示系统中的用户。
type User struct {
    Name string
}

// Add 返回 a 与 b 的和。
func Add(a, b int) int {
    return a + b
}
```

### 包注释

每个包应该有包级注释，放在一个文件里（通常 doc.go）：

```go
// Package user 提供用户相关的数据结构与操作。
package user
```

### 注释风格

- 一句话开头，句号结尾
- 解释"为什么"而不是"做什么"（代码已经说明做什么）
- 不要写实现细节流水账

### 生成文档

```powershell
go doc ./user          // 命令行看包文档
godoc -http=:6060      // 本地网页看全套文档
```

### 代码可读性优先

Go 哲学：代码被阅读的次数远多于被编写的次数。好名字胜过注释，清晰结构胜过华丽注释。

## 核心重点
- 导出符号必须注释，且以名字开头
- 包注释写包级说明
- 注释解释为什么，不是复述代码
- go doc 直接从注释生成
- 好命名 > 好注释

## 练习/任务
1. 给自己写的包补全包注释
2. 给所有导出函数写规范注释
3. 运行 `go doc ./你的包` 看效果
4. 故意把注释改成"做什么"的废话，体会差距
