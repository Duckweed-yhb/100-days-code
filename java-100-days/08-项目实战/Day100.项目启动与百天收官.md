## 今日目标

- 想清楚「项目到底什么时候开始」，不被别人的节奏带着跑
- 理解为什么源文案建议「尽量往后放」项目
- 把本阶段 Day96–Day99 的项目观串成一条完整决策链
- 完成 100 天学习路线的收官，明确下一阶段该干什么

## 学习内容

- **核心问题**：什么时候开始做项目？
  - 源文案原文：什么时候开始？因人而异，没有标准，结合你现在的进度、时间、知识掌握程度来自己安排
- 源文案的建议：
  - 源文案原文：我建议尽量往后放，因为当你知识沉淀积累到一定程度后，你对项目各个技术栈的理解是会不一样的。也就更容易有自己的思考与理解
- 本阶段回顾（Day96–Day99 决策链）：
  - Day96 定位：简历至少两个项目，有实习可减到一个，没实习必须两个
  - Day97 思维：面试官看的是你的思考 / 理解 / 创新，不是项目名头
  - Day98 避坑：极力避开人手一份的烂大街项目——项目无罪，但用的人多了就有罪了
  - Day99 方向：不推荐具体项目，推荐做 Java 结合 AI 的方向

## 核心重点

- 启动时机：因人而异、没有标准答案
- 判断依据：结合自己现在的进度、时间、知识掌握程度自行安排
- 总体倾向：尽量往后放，别急着一上来就扎进项目
- 原因：知识沉淀到一定程度后，对项目各技术栈的理解会不一样
- 延后的红利：理解越深，越容易产生自己的思考与理解（呼应 Day97 的亮点要求）
- 收官认知：100 天打下的语法、数据库、并发、算法底子，正是「往后放项目」的底气所在

## 练习/任务

1. 对照「进度 / 时间 / 知识掌握程度」三要素，给自己定一个项目启动的大致时间点
2. 把 Day96–Day99 的四条结论整理成一页「项目决策清单」存档
3. 为下一阶段列出：选定方向（Java + AI）、攒够两个项目、每个项目都要能讲出自己的亮点
4. 复盘这 100 天：哪些阶段最扎实、哪里还需要回头补
