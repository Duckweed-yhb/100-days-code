# Day 23 · 内存布局与调试工具

## 今日目标

- 知道代码段、数据段、BSS、堆、栈分别放什么

## 学习内容

### 一个 C 程序的内存布局

进程启动后，虚拟地址空间从低到高大致是：

```
高地址
  栈 (stack)      ← 局部变量、函数参数，向下增长
       ↓
       （空闲）
       ↑
  堆 (heap)       ← malloc 分配，向上增长
  BSS段           ← 未初始化的全局变量
  数据段          ← 已初始化的全局变量
  代码段 (text)   ← 编译后的机器码、字符串常量，只读
低地址
```

### 各段详解

| 段 | 存放内容 |
|---|---|
| 代码段 text | 程序指令、字符串字面值，只读 |
| 数据段 data | 已初始化的全局变量、static 变量 |
| BSS | 未初始化的全局变量，程序启动时清零 |
| 堆 heap | malloc/realloc 动态分配，手动 free |
| 栈 stack | 函数调用栈帧、局部变量、返回地址 |

```c
int g1;                 // BSS
int g2 = 100;           // data
static int g3;          // BSS（文件内可见）
const char *s = "hi";   // s 在 data，"hi" 在 text
void func(void) {
    int x = 1;          // 栈
    int *p = malloc(4); // p 在栈，分配的内存在堆
}
```

### 栈的特点

- 自动分配释放，函数调用时压栈，返回时弹栈
- 大小有限（Windows 默认 1MB），递归太深会栈溢出
- 访问极快

### 堆的特点

- 手动管理，malloc/free
- 大小几乎无上限（受物理内存限制）
- 分配释放有开销，频繁小块分配会碎片

### gdb 入门（Linux/WSL）

```bash
gcc -g test.c -o test      # -g 加入调试信息
gdb ./test
```

gdb 常用命令：

| 命令 | 作用 |
|---|---|
| `b 行号` | 在某行设断点 |
| `run` | 启动程序 |
| `next` / `n` | 单步（不进函数） |
| `step` / `s` | 单步（进函数） |
| `print 变量` / `p 变量` | 打印变量 |
| `bt` | 查看调用栈 |
| `continue` / `c` | 继续到下一个断点 |
| `quit` | 退出 |

### Windows 上调试

- Visual Studio：F5 启动调试，F10 单步，F11 进入函数，鼠标悬停看变量
- VS Code：装 C/C++ 扩展，按 F5 选 GDB/LLDB 或 CDB

### 不依赖调试器的调试

初学者最常用、最有效的手段——**加 printf**：

```c
printf("debug: i=%d, sum=%d\n", i, sum);
```

把怀疑出错的位置前后的变量打印出来，看哪一步开始不对。这不是低级手段，是工程师日常。

## 核心重点
- 内存五段：代码、数据、BSS、堆、栈
- 局部变量在栈，malloc 在堆，全局变量在数据/BSS
- 栈自动管理但小，堆手动管理但大
- gdb：b 打断点、n 单步、p 打印、bt 看栈
- printf 调试永远有效
