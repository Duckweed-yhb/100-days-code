# Day 11 · 一维数组

## 今日目标
- 掌握一维数组的声明、初始化与访问
- 理解数组在内存中的连续存储
- 能用数组解决批量数据处理问题

## 学习内容

### 声明与初始化

```c
int scores[5];                 // 声明长度为5的数组，内容未初始化
int nums[5] = {1, 2, 3, 4, 5}; // 声明同时初始化
int a[] = {10, 20, 30};        // 编译器自动推断长度为3
int b[5] = {1, 2};             // 前两个为1,2，其余自动为0
int c[5] = {0};                // 全部清零
```

### 访问元素

数组下标从 **0** 开始：`nums[0]` 是第一个元素，`nums[4]` 是第五个（最后一个）。

```c
int nums[5] = {10, 20, 30, 40, 50};
printf("%d\n", nums[0]);   // 10
printf("%d\n", nums[4]);   // 50
nums[2] = 99;              // 修改第三个元素
```

**越界访问是 C 最常见的 bug 来源**：`nums[5]` 访问的是数组后面相邻的内存，编译器不报错，但会踩坏别的数据。写循环时一定要确认下标范围是 `0 ~ n-1`。

### 遍历数组

```c
int nums[5] = {3, 1, 4, 1, 5};
int n = 5;
for (int i = 0; i < n; i++) {
    printf("%d ", nums[i]);
}
```

### 数组做函数参数

数组名传给函数时，**退化成指针**，函数内部无法知道数组长度：

```c
void print_arr(int arr[], int n) {   // 必须额外传长度
    for (int i = 0; i < n; i++) {
        printf("%d ", arr[i]);
    }
}
```

这就是为什么数组做参数时总是要额外传一个 `n`——函数里 `sizeof(arr)` 拿到的是指针大小（8 字节），不是整个数组大小。

### 常见算法模板

**求最大值**：

```c
int max = arr[0];
for (int i = 1; i < n; i++) {
    if (arr[i] > max) max = arr[i];
}
```

**求平均值**：

```c
int sum = 0;
for (int i = 0; i < n; i++) sum += arr[i];
double avg = (double)sum / n;
```

**查找**：

```c
int target = 4;
int found = -1;
for (int i = 0; i < n; i++) {
    if (arr[i] == target) { found = i; break; }
}
```

### 数组在内存中

数组元素在内存里**连续存放**。`int a[5]` 占 5×4=20 字节，`a[0]` 紧挨着 `a[1]`，以此类推。这个特性是后面指针算术、缓存友好性的基础。

## 核心重点
- 数组下标从 0 开始，长度为 n 的数组合法下标是 0~n-1
- 越界访问不报错但会踩坏内存，是最危险的 bug
- 数组做函数参数时退化成指针，必须额外传长度
- 连续内存存储是数组性能高的根本原因
- 求最大、求和、查找是数组三大基本操作
