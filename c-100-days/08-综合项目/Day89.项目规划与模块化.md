## 学习内容

### 项目为什么要模块化

一个文件塞 1000 行代码，谁都看不懂。拆成多个文件，每个文件负责一件事，才能维护。

### 模块化原则

- 一个 .c 文件对应一个 .h 文件
- .h 放接口（声明），.c 放实现
- 文件间通过头文件通信
- 高内聚低耦合：模块内紧密，模块间尽量少联系

### 例子：学生管理系统

```
student/
 ├─ student.h    // 类型定义、函数声明
 ├─ student.c    // 增删改查实现
 ├─ storage.h    // 文件存储接口
 ├─ storage.c    // 读写文件实现
 ├─ ui.h         // 菜单接口
 ├─ ui.c         // 菜单循环
 └─ main.c       // 入口
```

### main.c 只做编排

```c
#include "student.h"
#include "ui.h"

int main(void) {
    StudentDB db;
    db_init(&db);
    db_load(&db, "students.dat");
    ui_run(&db);
    db_save(&db, "students.dat");
    db_free(&db);
    return 0;
}
```

main 不关心具体怎么增删查，只负责流程。

### 头文件写什么

- #ifndef 卫士
- 类型定义（typedef struct）
- 宏定义
- 函数原型
- 不写函数实现、不分配变量

## 核心重点
- 模块化：一个 .c 一个 .h
- .h 是接口，.c 是实现
- main 只编排
- 高内聚低耦合
- 头文件卫士必备
