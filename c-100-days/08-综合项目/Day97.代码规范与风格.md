# Day 97 · 代码规范与风格

## 今日目标
- 写出可读的 C 代码
- 掌握命名、缩进、注释规范
- 知道常见反模式

## 学习内容

### 为什么代码规范

代码被读的次数远多于写的次数。可读代码 = 好维护。

### 命名

- 变量函数：小写加下划线 `student_count`
- 宏常量：全大写下划线 `MAX_SIZE`
- 类型名：大驼峰 `Student`
- 见名知意，别用 `a, b, tmp` 除非真的是临时

```c
int student_count;       // 好
int n;                   // 也行，短函数里
int x1, x2, x3;          // 不好
```

### 缩进与大括号

推荐 4 空格，K&R 风格：

```c
int add(int a, int b) {
    if (a > b) {
        return a;
    } else {
        return b;
    }
}
```

### 注释

- 为什么这么写，而不是做了什么
- 公共头文件函数要注释
- 复杂逻辑注释
- 不要废话：`i++ // i加1`

### 头文件卫士

永远写：

```c
#ifndef STUDENT_H
#define STUDENT_H
...
#endif
```

### 常见反模式

- 魔数：`if (status == 5)` 应该用 `#define ERROR_FILE_NOT_FOUND 5`
- 过长函数：超过 50 行考虑拆
- 过深嵌套：超过 3 层用早返回
- 全局变量满天飞
- 不检查返回值

### 早返回

```c
// 不好
int process(int x) {
    if (x > 0) {
        if (x < 100) {
            return x * 2;
        }
    }
    return -1;
}

// 好
int process(int x) {
    if (x <= 0) return -1;
    if (x >= 100) return -1;
    return x * 2;
}
```

## 核心重点
- 命名见名知意
- 注释写为什么
- 头文件卫士必备
- 早返回减少嵌套
- 检查每个返回值
- 代码是给人读的
