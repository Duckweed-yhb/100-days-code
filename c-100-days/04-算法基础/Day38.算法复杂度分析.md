## 学习内容

### 为什么要分析复杂度

两个程序都能跑，但一个 1 毫秒一个 1 小时，差距在哪？复杂度分析回答"数据量增大时，算法变慢多少"。

### 大 O 表示法

描述算法运行时间随输入规模 n 增长的**上界**，忽略常数和低阶项：

| 复杂度 | 名称 | 例子 |
|---|---|---|
| O(1) | 常数 | 数组按下标访问 |
| O(log n) | 对数 | 二分查找 |
| O(n) | 线性 | 遍历数组 |
| O(n log n) | 线性对数 | 快速排序、归并排序 |
| O(n²) | 平方 | 冒泡排序、双重循环 |
| O(n³) | 立方 | 三重循环 |
| O(2ⁿ) | 指数 | 朴素子集枚举 |
| O(n!) | 阶乘 | 全排列 |

### 怎么算

**顺序执行**：各段相加，取最大阶。
**循环**：循环次数 × 循环内复杂度。
**嵌套循环**：相乘。

```c
// O(n)
for (int i = 0; i < n; i++) { ... }

// O(n²)
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++) { ... }

// O(n log n)：外层 n 次，内层 log n
for (int i = 1; i < n; i *= 2) { ... }
```

### 空间复杂度

类似地，描述额外空间随 n 增长：

```c
int *a = malloc(n * sizeof(int));   // O(n) 空间
```

递归的栈空间也要算：递归深度就是空间复杂度。

### 最好/最坏/平均

- 最好情况：数据已经排好序时冒泡 O(n)
- 最坏情况：逆序时冒泡 O(n²)
- 平均情况：期望

面试和工程主要看最坏情况。

### 常见复杂度速查

n = 10^6 时：
- O(n)：约 1 毫秒
- O(n log n)：约 20 毫秒
- O(n²)：10^12 次操作——**跑一年都跑不完**

所以遇到 n > 10^4 还 O(n²) 的算法就要警惕了。

## 核心重点
- 大 O 描述增长趋势，忽略常数
- 常见量级：O(1) < O(log n) < O(n) < O(n log n) < O(n²)
- 顺序加、嵌套乘
- 递归深度算空间
- 面试看最坏情况
