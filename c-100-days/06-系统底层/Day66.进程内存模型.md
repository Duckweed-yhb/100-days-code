# Day 66 · 进程内存模型

## 今日目标
- 深入理解 C 程序内存五段
- 理解虚拟地址空间
- 知道栈和堆的实际布局

## 学习内容

### 回顾 Day23

```
高地址
  栈 stack        ← 局部变量、函数参数
  |
  v 向下增长
  
  ^ 向上增长
  |
  堆 heap         ← malloc
  BSS             ← 未初始化全局
  数据段          ← 已初始化全局
  代码段 text     ← 指令、字符串常量
低地址
```

### 代码段 text

- 程序指令，只读
- 字符串字面值也在这里（只读，所以不能改）
- 多个进程运行同一程序共享代码段

### 数据段与 BSS

- 数据段：已初始化全局变量，可读可写
- BSS：未初始化全局变量，启动时清零，不占可执行文件空间

```c
int a = 10;       // 数据段
int b;            // BSS
static int c = 5; // 数据段
static int d;     // BSS
```

### 堆

- malloc 分配
- 向上增长
- 由程序员管理
- 用 brk/mmap 系统调用扩展

### 栈

- 向下增长
- 每个函数调用压一帧
- 包含返回地址、参数、局部变量、保存的寄存器

### 虚拟地址

每个进程看到的都是独立的 4GB（32 位）或更大虚拟地址空间。物理内存由 OS 映射。所以进程 A 的地址 0x4000 与进程 B 的 0x4000 指向不同物理内存，互相隔离。

### 为什么栈很小

栈默认只有几 MB，因为它是紧急用的，大对象应该放堆。递归太深栈溢出就是栈不够大。

## 核心重点
- 五段：text、data、BSS、heap、stack
- 代码段只读，字符串常量在这里
- 堆向上、栈向下，相向增长
- 每个进程有独立虚拟地址空间
- 栈小（MB 级），堆大（GB 级）
