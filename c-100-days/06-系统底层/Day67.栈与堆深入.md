# Day 67 · 栈与堆深入

## 今日目标
- 理解函数调用栈帧结构
- 知道栈溢出原因
- 理解 malloc 底层大致原理

## 学习内容

### 栈帧里有什么

每次函数调用，栈上压入一帧，大致包含：
- 返回地址（caller 下一条指令）
- 旧基址指针
- 函数参数
- 局部变量
- 临时值

```c
void func(int a, int b) {
    int x = 1;
    int y = 2;
}
```

调用 `func(3, 5)` 时栈上（从高到低）：

```
返回地址
旧 ebp
a = 3
b = 5
x = 1
y = 2
```

### 栈溢出

递归太深或局部数组太大，栈不够用就崩溃。常见原因：
- 无限递归
- 函数内声明大数组（如 `int buf[1000000]`）
- 分配大对象应该用 malloc

### 栈上分配 vs 堆上分配

```c
int a[100];              // 栈上，函数返回自动回收
int *p = malloc(400);    // 堆上，手动 free
```

### malloc 底层（大致）

- 维护一个空闲块链表
- 分配时找一块够大的
- 释放时合并相邻空闲块
- 不直接还给 OS（大多数情况），留给下次 malloc

glibc 的 ptmalloc、Windows 的 HeapAlloc 都很复杂。我们只要知道：malloc 有开销，频繁小块分配慢。

### 内存碎片

- 外部碎片：空闲内存很多但都不连续，没法用
- 内部碎片：分配的块比请求的大

### 栈对齐与 padding

编译器为了访问效率，会在结构体成员间填充字节。这就是为什么 `sizeof(struct { char a; int b; })` 不是 5 而是 8 或 12。

## 核心重点
- 栈帧：返回地址 + 参数 + 局部变量
- 栈溢出 = 递归太深或栈上大数组
- malloc 从堆上分配，有开销和碎片
- 大对象用堆，小临时变量用栈
- 结构体会对齐 padding
