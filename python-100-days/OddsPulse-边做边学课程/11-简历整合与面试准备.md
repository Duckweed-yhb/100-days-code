- 过一遍"抗问穿清单"，能从容回答面试官追问

## 前置要求
- 完成课 10（README 发布）

## 最小知识
**简历项目段写法**（career-os 规范）：动词 + 技术细节 + 量化结果，每项目 2-3 条。示例方向：

> - 设计并实现 **OddsPulse** 预测市场数据源+分析框架：接入 Polymarket/Kalshi 公开 API，统一为 `Market` 数据模型，数据落地 SQLite（Python / httpx / Pydantic / sqlite3）
> - 实现市场提取打分、概率变化追踪与异常信号检测等纯函数分析模块，pytest 覆盖 N 个用例
> - 接入 LLM Agent 判断层，将分析信号转化为结构化 `MarketVerdict` 输出，含失败兜底与容错

> ⚠️ 数字必须是**真实的**（真跑了几个数据源、真写了几个测试、真分析了多少个市场）。不允许编造。

**抗问穿清单**——每个项目都要能不假思索回答：
1. 为什么选 Python / SQLite / 这个接口抽象？备选是什么、权衡是什么？
2. 极端情况会坏在哪（API 挂了、数据缺字段、LLM 返回垃圾）？你怎么处理？
3. 哪些是你独立做的，哪些参考了 TradingAgents？边界在哪？
4. 如果重做你会改哪里、为什么？
5. 哪个数字能证明它真的 work（拉了多少市场、测试几个、一次 run 多快）？

## 动手任务
1. 按上面格式，把 OddsPulse 写成简历上的 2-3 条（先草稿，再精修）。
2. 把"抗问穿清单"5 个问题的答案各写 2-3 句（这就是你的面试底稿）。
3. 对着课程里每个模块，确认你能讲清它的输入、输出、为什么存在。
4. 把简历 PDF + 仓库链接整理成提交材料，按 ARTi 投递要求发出。

## 验收标准
- [ ] 简历项目段有量化结果，且所有数字真实
- [ ] 抗问穿 5 题都能流利答出
- [ ] 提交材料齐备（GitHub 仓库链接 + 简历 PDF）
- [ ] 已正式投递

## 常见坑
- 简历堆技术名词没结果 → 每条都带一个真实数字或结果。
- 答不出"为什么这么设计" → 面试会在这里穿帮，提前写底稿。
- 把 TradingAgents 的功劳说成自己的 → 明确说"参考了它的结构，我自己实现的是……"。
