# Day 55 · 垃圾回收GC机制

## 今日目标
- 理解 .NET 自动内存管理：GC 怎么工作
- 知道代龄（Generation）与回收时机
- 学会写对 GC 友好的代码

## 学习内容

### GC 是什么

C++ 里你要手动 `new` / `delete`，忘 delete 就内存泄漏。C# 不用：GC（Garbage Collector）定期扫描堆，**没有任何引用指向的对象**就回收。

```csharp
void M()
{
    var s = new Student();
    s.Name = "A";
}   // 方法返回，s 出作用域，对象没人引用，将来被 GC
```

### 代龄（Generation）

GC 把堆分三代：

- **第 0 代**：刚 new 出来的小对象；
- **第 1 代**：熬过一次 GC 的；
- **第 2 代**：老对象（长生命周期，如静态对象）。

大部分回收发生在第 0 代，很快。第 2 代回收慢，要尽量少触发。

### GC 什么时候跑

- 分配内存不够时；
- 代码手动 `GC.Collect()`（一般别调）；
- 低内存时。

### 析构与终结器（了解）

```csharp
class FileWrapper
{
    ~FileWrapper()    // 终结器，很少写
    {
        // 释放非托管资源
    }
}
```

> 实际项目里释放资源用 `IDisposable`（明天），别靠终结器。

### 写对 GC 友好的代码

| 做法 | 说明 |
|---|---|
| 避免在循环里 new 大对象 | 减少第 0 代压力 |
| 用 struct 装小值类型 | 避免堆分配 |
| 别频繁拼接字符串 | 用 StringBuilder（Day57） |
| 大对象用完及时置 null | 帮助 GC 尽早发现 |
| 别手动 GC.Collect() | 除非特殊性能场景 |

## 核心重点
- GC 自动回收无引用对象
- 分 0/1/2 代，第 0 代最频繁最快
- 大部分时候不用管 GC，但要懂它
- 避免短时间大量分配
- 释放资源用 IDisposable，别靠终结器
